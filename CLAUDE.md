# SimultanAI

- All AI provider logic lives in `server/src/providers/impl/`; `translator.ts` and `index.ts` only see the contract in `provider.ts`. New provider = one file in `impl/`, one line in the factory, tests on `setupMessage()` and `parse()`. One session produces ONE language: N languages = N sessions fed with the same audio.
- The input sample rate is a constraint of each AI provider, so the provider code declares it (`inputSampleRate` variable) and ffmpeg produces it (`audio_rate` in `client/_common.sh`). The server never resamples, by design: ffmpeg normalizes. If the two values don't match, the pitch changes with no error in the logs.
- The server keeps in RAM who sends the audio (`ingest` in index.ts) and who listens (`rooms` in broadcast.ts): it must run as a single instance. With two replicas the audio reaches one and half of the listeners reach the other, which stays silent with no errors.
- ffmpeg sends the audio as a single `POST /ingest` that lasts the whole event. Node closes it after 5 minutes by default, which is why `server.requestTimeout = 0` is mandatory. But without a timeout an unplugged cable is never detected (a dead TCP connection sends no FIN) and provider sessions stay open and billed for hours: so the server drops the ingest and closes the sessions after `INGEST_IDLE_MS` without receiving bytes.
- `TARGET_LANGS` on the server is the only source of languages. The page reads them from `GET /info` through the Next route handler (server side, bearer `INFO_TOKEN`); the browser talks to the server only via WebSocket, so no CORS. Never hardcode languages in `web/`.
- `GET /health` answers only `ok`/`unavailable`, the data lives in `/info`. The provider probe is a free `models.get`: never open a session or send content, realtime sessions are billed per minute even in silence.
- `NEXT_PUBLIC_SERVER_URL`: without the prefix it is `undefined` in the browser with no errors, and it is inlined at build time (changing it = new build). Next reads only `web/.env*`, so `web/next.config.mjs` loads the root `.env`; variables already in the environment (Vercel) win.
- The server is not compiled: Node 24 runs the `.ts` files directly, ignoring types. Checks are done only by `npm run verify` in `server/` (types, lint, tests) and `npm run check` in `web/` (types), and a Stop hook in `.claude/` blocks me until both are green. TypeScript stays at 6: typescript-eslint does not support 7. Dependency versions always verified on npm, never from memory.
- Tests in `server/test/` never open the network: instead of the provider and the WebSocket they use `FakeProvider` and `FakeSocket` from `helpers.ts`, and time is simulated with `t.mock.timers`.
- Any change or test that may incur costs on the AI provider must be flagged before doing it. Realtime sessions are billed per minute even in silence; `/health` instead checks the provider with a free call (`models.get`).
- Session expiry: OpenAI announces it (`session.created.expires_at`), Gemini does not: the provider emits `expires` at setupComplete + 10 min and the Translator also rotates on `goAway`. The old session must be drained with 10 s of silence, otherwise it never emits the last sentence. `ROTATE_MARGIN_MS` exists only to test rotation.
- Gemini: `setup` must be the first frame; `outputAudioTranscription` goes at `setup` level, NOT in `generationConfig` as in the Live translation guide example (there it closes with 1007); `translationConfig` lives in `generationConfig`; JSON frames may arrive as binary; the key is in the URL, never log the URL.
- Unmapped provider events arrive as `unknown` and are logged once per type: read the server logs before inventing names.
- `/listen` requires a `ticket`: JWT HS256 signed in `web/app/ticket.ts` (Server Action, 50 s) and verified in `server/src/ticket.ts` with the same `LISTEN_SECRET`. Never give the secret the `NEXT_PUBLIC_` prefix. A mismatch (different secret, algorithm, or clocks more than 50 s apart) shows up only as every listener closed with 4001.
- Listeners receive Opus, never PCM: `broadcast.ts` encodes once per language (`opus.ts`, 20 ms packets, `libopus-wasm`) and the page decodes with WebCodecs `AudioDecoder`. WASM on purpose: `@discordjs/opus` has no Node 24 prebuild (Alpine would have to compile it) and `@evan/opus` is glibc-only and falls back to WASM silently. A listener with more than `MAX_BUFFERED_BYTES` queued is closed with 4002.
- CSS in `web/`: native nesting and declarations in alphabetical order within each rule. No tool enforces this.
